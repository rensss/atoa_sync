# Android 端界面与交互重设计

日期：2026-09-23
状态：待书面审阅
范围：Android UI

## 背景与目标

Android 端已有媒体库、相册目录树、同步前确认、传输状态、设置和媒体预览。当前界面以程序化 Android View 逐页构建，视觉层级和控件样式分散；相册筛选会重新渲染整页，容易丢失浏览位置。B17–B21 已完成上一轮 Android UI 改版，B33 增加前台同步服务，B38 增加相册目录层级与通知点击返回。既有记录中的完整真机 UI QA 尚未完成。

本设计针对 Android 手机用户在媒体库中浏览、选择本次上传内容、查看传输进展和配置接收目标的日常操作。目标是建立一致、清晰的深色专业工具界面，并改善页面层级、状态可见性和操作反馈，同时保留既有同步能力和数据语义。

## 已确认决策

- 视觉方向采用深色专业工具风格；媒体浏览与传输状态在首页保持均衡呈现。
- 采用 Android 原生 View，沿用 Java 和现有构建脚本，不引入 Compose、Gradle 或第三方 UI 依赖。
- 保留“媒体库 / 设置”两个主入口。相册管理、同步确认和预览作为从属界面；活动传输详情采用媒体库内打开的底部抽屉。
- 允许调整传输 UI 的入口和反馈呈现；开始确认、停止、失败重试及任务状态语义保持不变。不增加暂停、续传、自动重试或其他传输能力。
- 保留既有功能、白名单和筛选含义、同步确认选择规则、通知行为及目标地址配置。
- 本轮面向当前竖屏手机，不扩展平板或横屏布局。

## 视觉系统

- 以石墨深色表面建立背景、内容层和浮层层级；正文、次要文字、边框和分割线使用稳定的对比层级。
- 主操作采用单一冷色强调色；成功、等待/提醒和失败使用易区分的语义状态色。弱化大面积装饰性渐变，避免状态色承担装饰用途。
- 统一字体等级、间距、圆角、边框、按钮、筛选 chip、列表行、状态 badge、对话框和系统栏外观。
- 触控目标不小于 48 dp；可交互控件提供清楚的按压状态、可读标签和无障碍描述；系统字体放大时不裁切核心操作。
- 图标使用一致的本地矢量/Drawable 资源或原生图标处理，不以混杂 Unicode 字符代替成套图标。

## 页面与交互

### 媒体库

- 保留媒体库和设置两个底部主导航项。
- 媒体库在同一页面展示标题、相册筛选、活动传输摘要和媒体网格；网格保留主要滚动空间。空闲且没有失败项时不显示空传输卡。
- 相册筛选继续保持现有多选语义；“管理相册”入口与筛选项视觉区分。筛选直接更新可见媒体，不重新扫描、不重建整页，并保留网格滚动位置和当前查看上下文。
- 保留每项当前同步状态标记和明确的“同步”主操作，点击后进入现有确认路径。

### 传输详情抽屉

- 点击媒体库的活动传输摘要打开自定义原生 View 底部抽屉，不增加导航 tab 或 UI 依赖。
- 抽屉展示当前任务汇总和现有任务状态；使用现有 `SyncQueue`/`TaskWindow` 数据，保留最多 40 项的有界窗口及剩余项提示。
- 沿用现有停止和失败项重试操作。任务进度通过已有前台服务事件/队列快照更新；不得因开关抽屉而重启、暂停或停止同步。
- 抽屉提供可见关闭按钮、返回键、点遮罩关闭和向下拖动关闭。关闭后媒体库恢复原滚动位置。

### 同步确认

- 仍默认选中全部未同步媒体；点击媒体缩略图只排除该媒体于本次同步。
- 底部固定确认区实时显示当前选中数量和总大小；清空选择时禁用开始按钮。取消或返回回到媒体库原位置。
- 不新增全选、按类型选择或更改队列的操作。

### 相册管理

- 保留现有目录树、父目录级联选择、部分选择状态和子相册单独勾选。
- 视觉上区分“选择目录”和“进入目录”；面包屑/返回上级路径清楚可见。完成后保留原有返回目标和 `bucket_id` 持久化格式。

### 设置与预览

- 设置以统一的分组行展示相册白名单数量、当前接收地址、编辑入口和版本信息；二维码深链更新地址后仍进入设置并显示原有反馈。
- 媒体预览使用一致的全屏查看界面，图片预览和视频交由系统播放器的行为保持不变；关闭后回到原媒体和滚动位置。

## 技术边界与接口

- `MainActivity` 继续拥有页面路由、扫描/确认流程、Service 命令及事件桥接；现有 UI view/host 回调可作局部调整以支持抽屉打开、关闭和刷新。
- 核心任务类型、队列、Service、SQLite schema、媒体扫描/筛选逻辑、相册白名单格式、HTTP 协议和 macOS 接收端均不变。无数据迁移和网络行为变更。
- 缩略图继续使用现有 `ThumbnailLoader`，任务列表继续使用有界窗口；UI 更新不得在队列锁内执行 I/O 或 bitmap 解码。
- 设备配置维持现有最低 API 26、目标 API 35 和竖屏约束。

## 空态、错误与生命周期

- 空媒体库、未配置相册、无待同步项和权限未授予/被拒绝时显示有解释的空态和现有可执行入口，不显示误导性的空进度状态。
- 上传失败仍显示现有错误内容和单项重试；不改变普通网络错误、服务端暂停和停止的既有分类逻辑。
- 目标地址不新增连通性探测或“在线”推断；仅展示当前配置值及编辑入口。
- Activity 退到后台时继续由原前台 Service 拥有传输；回到前台/抽屉重新打开时读取最新队列快照。

## 验收标准

- `./android/run_tests.sh` 与 `./android/build.sh` 通过；不新建 UI 自动化框架。
- 真机检查相册目录选择与返回、筛选保留网格位置、确认排除后的数量/大小、图片/视频预览返回、底部抽屉实时任务状态/停止/重试、设置改地址，以及通知点击回到前台后传输继续。
- 在常用竖屏手机上确认层级清楚、控件样式一致、无文字裁切、触控目标可用；至少覆盖系统字体放大。
- 复核风险 R-001（缩略图与内存）和 R-002（大型媒体库/有界 UI 更新），保留当前控制措施；仅完成 UI 测试和构建不代表风险关闭。
- 当前开发环境未连接 Android 设备。真机 QA 是最终完成标准，设备验收未完成时必须明确记录。
